# astrbot_plugin_keyword_watch

> 群成员自助订阅关键词，命中就私聊提醒本人。

在群里发一句 `/设置关键词提醒 紧急`，之后谁在群里提到「紧急」，机器人就私聊你。

不需要管理员预先配规则——谁想盯什么词，自己设。

## 为什么需要它

群聊信息太密，重要的那几句很容易被刷过去。让管理员替每个人配关注词不现实，而关键词回复类插件往往是把提醒发回群里——那只是多刷一条消息，该看到的人还是可能错过。

这个插件的做法是：**提醒只私聊发给关心这件事的人**。谁订阅、谁收到，群里保持安静。

## 特性

- **自助订阅**：任何群成员发一条指令就能设，不用管理员介入
- **按群隔离**：关键词只在设置它的那个群生效，不会被其他群的无关消息打扰
- **两种写法**：直接写 `紧急` 是包含匹配；写 `/订单\d+/` 按正则匹配，添加时校验语法
- **合并通知**：一条消息同时命中你多个关键词，只提醒一次并列出全部命中词
- **冷却防刷屏**：同一群同一人默认 60 秒内最多收一条
- **不打扰群聊**：只监听不拦截，不影响群里正常的 LLM 对话
- **数据不丢**：订阅持久化到 `data/plugin_data/`，写盘原子替换，文件损坏能自愈

## 安装

要求 **AstrBot >= 4.9.2**，平台为 aiocqhttp / NapCat。

```bash
cd AstrBot/data/plugins
git clone https://github.com/MikatoMisaka/astrbot_plugin_keyword_watch.git
```

然后在 WebUI 插件页点刷新，或重启 AstrBot。

也可以直接下载仓库 zip 解压到 `AstrBot/data/plugins/` 下。

装好后在 WebUI 的插件配置里能看到本插件，无需额外配置即可使用。

## 使用

所有指令都在**群里**发送（关键词只在发指令的那个群生效）。

| 指令 | 作用 |
| --- | --- |
| `/设置关键词提醒 紧急` | 订阅关键词「紧急」 |
| `/设置关键词提醒 /订单\d+/` | 用正则订阅，`/.../` 包起来即按正则处理 |
| `/我的关键词提醒` | 查看自己在所有群订阅了什么（优先私聊发送） |
| `/删除关键词提醒 紧急` | 取消订阅这一个 |
| `/清空关键词提醒` | 清空自己在当前群的全部订阅 |

### 一次完整的对话

```
用户A  /设置关键词提醒 紧急
机器人  ✅ 已订阅「紧急」（1/20）
        （同时私聊：在「摸鱼群」订阅「紧急」成功，命中会私聊提醒你）

用户B  老板：有紧急情况，今晚可能要加班
机器人  → 私聊用户A：

        【关键词提醒】
        群：摸鱼群（123456789）
        发送人：用户B（222333）
        时间：2026-10-22 20:15:03
        命中：紧急
        内容：老板：有紧急情况，今晚可能要加班
```

### 行为约定

- **只在设置它的群生效**。A 群设的词，B 群有人提到不会通知你。
- **自己发的消息不提醒自己**。别人说到你订阅的词才会提醒（配置项 `notify_self` 可打开）。
- **一条消息只提醒一次**。同一条消息命中你多个关键词时合并成一条，`{keywords}` 列出全部命中词。
- **指令消息不参与匹配**。别人发 `/设置关键词提醒 紧急` 不会立刻触发所有订阅了「紧急」的人。
- **收不到私聊说明没加机器人好友**。这是 OneBot 的限制，单向好友发不出去。

## 配置

WebUI → 插件 → 本插件 → 配置。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 插件总开关 | 开 | 关掉后停止监听，数据保留 |
| 每人每群最多订阅数 | 20 | 防止刷订阅 |
| 关键词最大长度 | 50 | 正则也受此限制 |
| 通知冷却（秒） | 60 | 同群同一人多少秒内最多收一条，0 表示不限 |
| 提醒消息模板 | 见下 | 全局生效 |
| 在群里回执 | 开 | 关掉后只在私聊回执，群里保持安静 |
| 私聊确认设置结果 | 开 | 顺便验证私聊通道是否通，建议开着 |
| 跳过指令消息 | 开 | 前缀开头的消息不参与匹配 |
| 指令前缀 | `/` | 上面那个判断用的前缀 |
| 自己也提醒 | 关 | 自己发的消息命中自己的词是否也提醒 |
| 时区偏移 | 8 | `{time}` 用的时区 |
| 单条提醒最大长度 | 1500 | 超出截断，防止超协议端限制 |

### 模板变量

| 变量 | 含义 |
| --- | --- |
| `{text}` | 消息原文 |
| `{sender}` | 发送者群名片/昵称 |
| `{sender_id}` | 发送者 QQ |
| `{group}` | 群号 |
| `{group_name}` | 群名 |
| `{time}` | 时间 |
| `{keywords}` | 本条消息命中的全部关键词，顿号分隔 |
| `{keyword}` | 第一个命中的关键词 |

默认模板：

```
【关键词提醒】
群：{group_name}（{group}）
发送人：{sender}（{sender_id}）
时间：{time}
命中：{keywords}
内容：{text}
```

变量名写错不会报错，会原样保留，所以看到花括号没被替换就是拼错了。

## 数据存储

订阅数据保存在：

```
AstrBot/data/plugin_data/astrbot_plugin_keyword_watch/subscriptions.json
```

```json
{
  "version": 1,
  "groups": {
    "群号": {
      "用户QQ": {
        "keywords": [
          { "kw": "紧急", "type": "text", "ts": 1690000000 },
          { "kw": "订单\\d+", "type": "regex", "ts": 1690000000 }
        ]
      }
    }
  },
  "group_names": { "群号": "摸鱼群" }
}
```

- 放在 `data/` 而不是插件目录，重装/更新插件不会丢
- 写盘用「临时文件 + 原子替换」，中途崩溃不会写坏
- 文件损坏时自动备份成 `subscriptions.broken.<时间戳>.json` 并重建空数据，不会让插件起不来
- 备份或迁移直接拷这个文件

## 排障

**设了关键词但收不到提醒**

1. 确认已加机器人为好友——最常见原因，单向好友发不出去
2. 群里发 `/我的关键词提醒`，确认订阅还在、在正确的群
3. 看 AstrBot 日志有没有 `群 xxx 命中「紧急」，已提醒 123456`
   - 有这行但没收到 → 送达问题（好友关系、风控）
   - 没这行 → 可能命中冷却，或者是自己发的消息

**设了关键词但一直不触发**

- 关键词是**包含匹配**：设「紧急」时「有紧急情况」能命中，「急」不能命中「紧急」以外的写法
- 确认发消息的群就是设置关键词的那个群
- 正则写错会在添加时直接拒绝，并给出 `re` 的报错信息

**想关掉某个群的提醒**

用户自己在那个群发 `/清空关键词提醒`；或管理员编辑 `subscriptions.json` 删掉对应节点后重载插件。

## 实现说明

想改代码或做二次开发可以看这里。

- 消息扫描只挂 `event_message_type(GROUP_MESSAGE)`，**不调用 `stop_event`**，所以群里正常对话和 LLM 回复完全不受影响
- 订阅按「群 → 用户 → 关键词列表」三级组织，扫一条消息只遍历**该群**的订阅者，不做全量遍历
- 文本关键词用 `in` 做包含匹配（大小写不敏感），正则关键词编译后缓存
- 写操作 `asyncio.Lock` 串行化，写盘丢进线程执行，不阻塞事件循环
- 扫描前对订阅字典做快照（`list(...)`），避免 `await` 期间数据变动导致遍历报错
- `skip_commands` 除了比对前缀，还会比对指令名——因为 AstrBot 唤醒阶段可能已经把 `/` 从 `message_str` 里剥掉
